# LaTeX Auditor Implementation Plan

## Objective
To create a robust, local technical auditing script (`report/audit.sh`) that acts as a comprehensive pre-submission verification tool for the ECM3175 Final Report. This script will ensure the structural integrity, stylistic correctness, and compilation success of the modular LaTeX project.

## Background & Motivation
The dissertation is heavily modularized across multiple chapters in `report/chapters/`. While `build.sh` currently automates compilation, it does not proactively identify common academic formatting issues (e.g., semantic LaTeX errors) or provide a clear summary of unresolved references or missing assets. An automated auditor mitigates the risk of submitting a document with broken citations or figures.

## Key Files & Context
- **Target Script:** `report/audit.sh` (new)
- **Target Source:** `report/chapters/*.tex` and `report/main.tex`
- **Build Script:** `report/build.sh` (existing)
- **Log File:** `report/out/main.log` (generated by build)
- **Tools:** `chktex` (installed locally)

## Implementation Steps

1. **Create the Skeleton Script (`report/audit.sh`):**
   - Initialize with a standard bash shebang (`#!/bin/bash`).
   - Add a brief description and set the script to exit on fatal errors (`set -e` where appropriate).

2. **Step 1: Linting with `chktex`:**
   - Loop through all `.tex` files in `report/` and `report/chapters/`.
   - Run `chktex` quietly on each file to flag common semantic LaTeX errors (e.g., incorrect quotation marks, unescaped percent signs, space before punctuation).
   - Summarize the warnings to the console.

3. **Step 2: Asset Verification (Images):**
   - Use `grep` to extract all instances of `\includegraphics[...]{filename}` or `\includegraphics{filename}` from the `.tex` source files.
   - For each extracted filename, verify its existence within the `report/figures/` directory (handling extensions like `.png`, `.pdf` if omitted).
   - Report any missing figures before compilation begins.

4. **Step 3: Compilation and Log Parsing:**
   - Execute the existing `report/build.sh` script to perform the actual PDF compilation.
   - Upon completion, parse the `report/out/main.log` using `grep` or `awk` to extract and count:
     - Undefined citations (`Warning: Citation...`).
     - Undefined references (`Warning: Reference...`).
     - Overfull and Underfull `\hbox` warnings (formatting issues).
   - Present a clear, color-coded summary report to the user in the terminal.

5. **Integration & Permissions:**
   - Ensure the new script is executable (`chmod +x report/audit.sh`).

## Verification & Testing
- **Dry Run:** Execute `./report/audit.sh` on the current state of the repository.
- **Error Injection:** Temporarily introduce a broken reference (`\ref{broken_label}`), a missing figure citation, and a common `chktex` error (e.g., `word .`) to confirm the script successfully catches and reports them.
- **Cleanup:** Revert the injected errors to ensure a clean build pass.

## Migration & Rollback
- Since this is an additive script, it does not interfere with the existing `build.sh` process. If the auditor fails or proves too noisy, the standard compilation via `./build.sh` remains unaffected.
